# RecipePro — подключение облака

RecipePro продолжает работать без аккаунта и интернета в пределах возможностей локального приложения. После настройки Supabase пользователь сможет входить по одноразовой ссылке из письма, а собственные рецепты и избранное будут синхронизироваться с облаком.

## 1. Создать бесплатный проект

1. Открой [Supabase Dashboard](https://supabase.com/dashboard).
2. Создай новый проект на Free Plan и дождись готовности базы.
3. Открой **SQL Editor** и выполни весь файл [supabase/schema.sql](../supabase/schema.sql).

Схема включает Row Level Security (RLS): пользователь может читать и менять только строку со своим `user_id`. В браузер нельзя помещать `service_role` или secret key.

## 2. Добавить параметры проекта

В Supabase открой **Project Settings → API Keys** (или **Connect**) и скопируй:
- Project URL;
- Publishable key (`sb_publishable_...`). Для старых проектов допускается legacy `anon` key.

Открой [JS/supabase-config.js](../JS/supabase-config.js) в GitHub и заполни значения:

~~~js
window.RECIPEPRO_SUPABASE_CONFIG = {
    url: "https://ТВОЙ-ПРОЕКТ.supabase.co",
    publishableKey: "ТВОЙ_PUBLISHABLE_KEY"
};
~~~

Publishable/anon key предназначен для клиентского приложения, но безопасность обеспечивают RLS-политики. **Не добавляй secret key или service_role key в репозиторий.**

## 3. Разрешить вход с сайта

В Supabase открой **Authentication → URL Configuration**:
- Site URL: `https://olegterekhov.github.io/RecipePro/`
- В Additional Redirect URLs добавь `https://olegterekhov.github.io/RecipePro/**`

Затем открой **Authentication → Providers → Email** и проверь, что вход по email включён. При необходимости настрой лимиты отправки писем.

## 4. Проверить

1. Открой опубликованный RecipePro и нажми **Облако**.
2. Введи свою почту и нажми **Получить ссылку для входа**.
3. Открой письмо и перейди по ссылке.
4. Добавь рецепт в избранное или создай свой рецепт, затем проверь таблицу `recipepro_user_data` в Supabase.
5. Войди с той же почтой на другом устройстве — данные должны появиться после синхронизации.

## Что уже предусмотрено

- локальное сохранение не отключается, если облако не настроено;
- при первом входе локальные данные объединяются с данными облака;
- синхронизируются собственные рецепты и избранное;
- у каждого пользователя отдельная строка, защищённая RLS;
- выход из аккаунта не удаляет локальные данные с устройства;
- при переключении между аккаунтами локальные данные разделяются по аккаунтам, чтобы не переносить рецепты одного пользователя в другой.

## Ограничения текущего этапа

Это первая версия облачной синхронизации. Сейчас синхронизируются только собственные рецепты и избранное; история, списки покупок и настройки пользователя пока не входят в облачную запись. Для полноценного публичного запуска отдельно проверим обработку конфликтов при одновременном редактировании на нескольких устройствах и настроим резервное копирование базы.
